# Robot-side hardware services

These packages run on the Raspberry Pi attached to the MD25 motor controller and MPU6050. Operator input, return planning and SLAM can run on the PC over the shared ROS 2 network. The original robot used ROS 2 Humble; the publication packages were also checked in a Jazzy build environment. Set the same ROS domain and compatible middleware configuration on both machines.

The node implementations are preserved. Packaging metadata and dependency declarations were cleaned up. The `mpu6050_ros2` package retains the original MIT declaration. The original `md25_simple` metadata had an unspecified license; its publication metadata uses `UNLICENSED`, which grants no open-source license. The separately referenced LDROBOT driver retains both original MIT notices.

## Build the two hardware packages

Run from the repository root on the robot, with the intended ROS installation sourced. Examples use the original Humble environment.

```bash
export ROVERLINK_ROOT="$PWD"
source /opt/ros/humble/setup.bash
sudo apt install python3-colcon-common-extensions python3-rosdep python3-venv python3-smbus python3-numpy
rosdep install --from-paths robot/ros2_ws/src --ignore-src -r -y
python3 -m venv --system-site-packages robot/.venv
robot/.venv/bin/python -m pip install -r robot/requirements-pip.txt
source robot/.venv/bin/activate
cd robot/ros2_ws
colcon build --symlink-install
source install/setup.bash
```

The virtual environment provides the external `mpu6050` module. Before running a console entry point, expose its site-packages to the system-Python executable generated by colcon:

```bash
export PYTHONPATH="$("$ROVERLINK_ROOT/robot/.venv/bin/python" -c 'import sysconfig; print(sysconfig.get_path("purelib"))')${PYTHONPATH:+:$PYTHONPATH}"
```

Linux permissions must allow access to I2C bus 1. Both hardware packages open that bus directly; no simulated hardware backend is supplied.

## Start the hardware nodes

Use separate robot terminals with the ROS installation and `robot/ros2_ws/install/setup.bash` sourced. Start the IMU/encoder node while stationary, then the motor driver. The IMU node resets encoder counts and spends approximately two seconds calibrating gyro and acceleration biases.

```bash
ros2 launch mpu6050_ros2 mpu6050.launch.py
```

```bash
ros2 run md25_simple md25_controller --ros-args \
  --params-file "$ROVERLINK_ROOT/robot/config/md25.yaml"
```

The reference configuration uses `speed_limit_steps: 35`, matching the recorded launch command: raw motor bytes range from 93 to 163 around neutral 128. It retains the original `invert_turn: true`, 0.05 deadband, and 0.2-second software command watchdog checked every 0.05 seconds. The implementation enables motor regulation and disables the MD25's hardware two-second timeout. The watchdog requires the driver process to remain responsive.

## Command and sensor contract

| Topic | Type | Meaning |
| --- | --- | --- |
| `/cmd_vel` | `geometry_msgs/Twist` | `linear.x`, `angular.z` are normalized demands in [-1, 1], not m/s or rad/s |
| `/robot/pose` | `geometry_msgs/Pose2D` | Encoder distance integrated using gyro heading; x/y metres, theta **degrees** |
| `/robot/pose_enc` | `geometry_msgs/Pose2D` | Encoder-only comparison pose; theta **degrees** |
| `/robot/imu` | `geometry_msgs/Twist` | angular.x raw gyro z rad/s, angular.y bias rad/s, angular.z heading degrees |
| `/robot/imu_raw` | `sensor_msgs/Imu` | Gyro rad/s and accelerometer readings; timestamp, frame and orientation are not filled |
| `/robot/distance_travelled` | `std_msgs/Float64` | Accumulated absolute mean wheel displacement, metres |

The pose implementation assumes 0.10 m wheel diameter, 360 ticks/revolution and 0.35 m wheel separation. It rejects encoder deltas larger than 40 ticks per update. These values and encoder signs require physical calibration. This package does not supply a standard Odometry message, TF broadcaster or Kalman filter; those are separate PC-side components/experiments.

Only one process may own motor commands. Do not launch the old direct-I2C return or supervisory controllers alongside `md25_simple`. The PC teleop node must stop publishing `/cmd_vel` when it hands control to autonomous return; there is no command multiplexer in the original implementation. For the extended return controller, use `avoid_turn_sign: -1.0` with this driver's default turn inversion. Keep its separate path-following `invert_turn: false` unless physical calibration establishes another convention.

## LD06 driver

Build the external driver in a separate workspace; it is pinned to the revisions present in both supplied robot folders. These commands check out upstream source and its SDK without modifying this repository.

```bash
mkdir -p "$ROVERLINK_ROOT/robot/ldlidar_ws/src"
cd "$ROVERLINK_ROOT/robot/ldlidar_ws/src"
git clone https://github.com/ldrobotSensorTeam/ldlidar_ros2.git
git -C ldlidar_ros2 checkout 0f6101c93db0b4448cbe7a654826adcdee50622f
git -C ldlidar_ros2 submodule update --init --recursive
git -C ldlidar_ros2/sdk checkout 6148cd3c33ae39adbd7e12faf82567fa8f8e7b0d
cd "$ROVERLINK_ROOT/robot/ldlidar_ws"
rosdep install --from-paths src --ignore-src -r -y
sudo apt install "ros-${ROS_DISTRO}-tf2-ros"
colcon build --symlink-install
source install/setup.bash
ros2 launch "$ROVERLINK_ROOT/dependencies/ldlidar/ld06.launch.py"
```

The adapted launch selects `/dev/ttyAMA0` and includes the sensor's static transform. Verify the serial device, access permissions and mounting offset before use; edit a local copy if the robot differs. Upstream origins, exact revisions and MIT notices are in [dependencies/ldlidar](../dependencies/ldlidar/README.md).

The public repository excludes original build/install/log folders, editor files, cached bytecode, generated package tests and unrelated controller alternatives. Hardware movement and I2C communication were not re-run during publication.
